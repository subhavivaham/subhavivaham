STEP 1 - Insert the public.users row                            [SQL Editor]
--------------------------------------------------------------------------------
insert into public.users (
  user_id, name, email, role, status,
  phone_number, is_membership_user, membership_plan, joined_at
) values (
  'user-admin', 'Subha Vivaham Admin', 'admintest@subhavivaham.com',
  'admin', 'active', '+919876543210', false, null,
  '2026-01-10T00:00:00.000Z'::timestamptz
)
on conflict (user_id) do update set
  name = excluded.name, email = excluded.email, role = excluded.role,
  status = excluded.status, phone_number = excluded.phone_number,
  updated_at = now()
returning *;

  DONE: 1 row returned. This also overwrites the seeded user-admin email.


STEP 2 - Create the Supabase Auth user                        [Dashboard]
--------------------------------------------------------------------------------
  Authentication -> Users -> Add user

    Email              admintest@subhavivaham.com
    Password           your choice - the only place it is ever set
    Auto Confirm User  TICK IT

  Skip Auto Confirm and sign-in fails with "Email not confirmed".


STEP 3 - Set the admin claim                                 [Dashboard / SQL]
--------------------------------------------------------------------------------
  THE STEP THAT IS EASY TO MISS. Without it you can log in but every admin
  table stays empty and you get bounced back to the login page.

  Dashboard: open the user -> Raw App Meta Data -> {"role":"admin"} -> Save
             (Raw App Meta Data, NOT User Meta Data)

  Or SQL:
    update auth.users
    set raw_app_meta_data = coalesce(raw_app_meta_data, '{}'::jsonb)
                            || '{"role":"admin"}'::jsonb
    where email = 'admintest@subhavivaham.com';


STEP 4 - Link the two                                         [SQL Editor]
--------------------------------------------------------------------------------
update public.users u
set auth_user_id = a.id, updated_at = now()
from auth.users a
where a.email = 'admintest@subhavivaham.com'
  and u.user_id = 'user-admin'
returning u.user_id, u.email, u.auth_user_id;

  DONE: 1 row with a real UUID. Zero rows = the auth email does not match.


STEP 5 - Verify all three                                     [SQL Editor]
--------------------------------------------------------------------------------
select u.user_id,
       u.email,
       u.auth_user_id is not null                 as auth_linked,
       a.email_confirmed_at is not null           as auth_confirmed,
       a.raw_app_meta_data->>'role'               as auth_role
from public.users u
left join auth.users a on a.id = u.auth_user_id
where u.user_id = 'user-admin';

  auth_linked    = true
  auth_confirmed = true
  auth_role      = admin        <-- if this is null, redo STEP 3

  All three true, then sign in.


STEP 6 - Sign in
--------------------------------------------------------------------------------
  Clear cookies for the site first (or hard refresh), then go to /admin/login.

  The old session token was minted before STEP 3, so it still carries no role
  and gets rejected. A stale cookie looks exactly like a broken app.
